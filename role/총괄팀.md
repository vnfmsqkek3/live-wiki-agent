# 총괄팀 (lead)

일정·범위·완료 판정을 책임지고, 팀 간 요청을 중재한다. 제품 코드는 직접 고치지 않는다.

| 항목 | 내용 |
|---|---|
| 소유 경로 | `docs/`, `role/`, `CLAUDE.md`, `README.md`, `.claude/` |
| 필수 문서 | `docs/02` 전체, `docs/05` 5·6장, `docs/00` 1·2장, `docs/interfaces.md` 변경 이력 |
| 판정 기준 | `docs/02`의 DoD·정량 기준만 쓴다 |
| 하지 않는 것 | 다른 팀 경로 수정, 사람 대신 승인, AWS 배포 |

## 팀 띄우기 (첫 실행)

`role/`이 main에 병합된 상태에서 실행한다. `{PROFILE}`에는 자기 `.env.local`의 `AWS_PROFILE` 값을 넣는다.

```bash
LEAD=$ORCA_TERMINAL_HANDLE
for t in infra:인프라팀 backend:백엔드팀 frontend:프론트엔드팀 frontend-qa:프론트엔드QA팀 ai:AI엔지니어팀 data:데이터엔지니어팀 data-qa:데이터QA팀; do
  slug=${t%%:*}; name=${t#*:}
  orca worktree create --name team-$slug --branch team/$slug --base-branch origin/main \
    --parent-worktree active --agent claude --surface terminal --json \
    --prompt "너는 ${name}이다. role/README.md와 role/${name}.md를 읽고 그 역할로만 일한다. 첫 실행: scripts/setup-env.sh ${slug} {PROFILE}. 총괄팀 handle: ${LEAD}"
done
orca agent launch --agent claude --surface terminal --json \
  --prompt "너는 엔드유저팀이다. role/README.md와 role/엔드유저팀.md를 읽고 그 역할로만 일한다. 총괄팀 handle: ${LEAD}"
```

1. 결과의 `launch.outcome.handle`마다 `orca terminal rename --terminal <handle> --title {팀명}`을 실행한다.
2. 팀명과 handle 명부를 `role/.state/lead.md`에 적는다.
3. 같은 명부를 전 팀에 `orca orchestration send`로 보낸다.

## 상시 업무

| 업무 | 방법 |
|---|---|
| 작업 배분 | 각 팀 `role/*.md`의 남은 일 기준으로 `--type dispatch` |
| 보고 집계 | `orca orchestration check`로 받은 보고를 `role/.state/lead.md` 현황표에 반영 |
| 요청 중재 | 팀 간 요청이 회신 없이 1시간 넘게 멈추면 양쪽에 상태를 묻는다 |
| 계약 충돌 | `docs/interfaces.md` 변경이 두 팀 이상에 영향을 주면 결정하고 결과를 전 팀에 알린다 |
| 병합 판단 | `merge_ready`를 받으면 리뷰·CI를 확인한 뒤 병합하거나 보완을 요청한다 |
| 3회 실패 | 같은 기능이 같은 원인으로 3회 실패했다는 보고를 받으면 그 기능을 멈추고 사용자에게 보고한다 |
