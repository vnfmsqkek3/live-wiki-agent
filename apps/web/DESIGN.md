# Hanaeum Wiki · Hana Design Guide 웹 적용

## 기준과 범위

저장소 밖의 `Hana Design Guide.pdf`(디지털 발표 디자인 가이드 v1.0)를 직접 읽었다. PDF는 복사·추가하지 않았다. 슬라이드의 1280×720와 본문 24px를 웹에 그대로 적용하지 않고 색·위계·강조 원칙을 적용했다. 변경은 `apps/web`에 한정한다. API 호출 경로·타입, 권한 분기, 분석·검토·승인 로직, Hanaeum Wiki 이름과 SYNTHETIC 고지를 유지한다. 실제 은행 로고는 사용하지 않는다.

## 색 토큰과 면적

`app/globals.css`에 가이드 토큰을 정의하고 기존 컴포넌트 변수는 해당 토큰의 별칭으로 연결했다.

| 계열 | 700 · 글자·아이콘·선 | 500 · 면·막대 | 050 · 옅은 배경 |
| --- | --- | --- | --- |
| Green | #00706B | #00A19B | #E6F5F3 |
| Sky | #1E63D6 | #6BA4F6 | #E9F1FE |
| Violet | #5B4BC4 | #9A8DE8 | #EFEDFB |
| Coral | #C2410C | #F26D1B | #FDEEE2 |

Navy: `--navy-900:#0A1C36`, `--navy-600:#274F80`, `--navy-050:#E8EDF4`. Ink: `--ink-700:#33465B`, `--ink-500:#64748B`. 경계: `--line:#DCE3ED`.

흰 화면·카드와 네이비 본문을 기본으로 한다. White 60 / Navy 20 / Green 12 / 보조 합계 8 이내를 강조 면적 기준으로 삼되 빈 화면을 비율에 맞춰 칠하지 않는다. 홈에서 그린 강조는 검색 영역 한 곳이다. 홈의 검증 배지는 아이콘·문구를 유지하며 네이비로 표시한다. 메뉴·계정·일반 버튼은 네이비다. 보조색은 정보용 Sky와 주의용 Coral 두 개만 실제 사용하고 Violet은 토큰만 준비했다. 범주 시각화의 순서는 Green → Sky → Violet → Coral → Navy, 초과 범주는 기타 #B9C4D3이다.

라이트에서 500 단계는 글자로 쓰지 않는다. 050 면에는 같은 계열 700 글자를 쓴다. 본문·상태의 색 조합은 대비 4.5:1 이상을 기준으로 선택한다. 면적 비율과 대비는 브라우저 픽셀 측정 결과가 아닌 설계 기준이다.

## 폰트와 숫자

- 제목 `--font-display`: IBM Plex Sans KR 600/700. 페이지 28–32px, 섹션 19.2px, 카드 18px.
- 본문 `--font-body`: Pretendard / Pretendard Variable 400/500/700. 본문 16px, 보조 14px, 고지 13px.
- 숫자 `--font-num`: IBM Plex Mono 500/600. 건수·날짜·쪽수·진행률·단계 번호에 사용한다.

`app/layout.tsx` head에 Google Fonts preconnect·stylesheet와 지정된 Pretendard CDN stylesheet를 추가했다. 패키지 설치나 빌드 시 다운로드는 없다. Google Fonts 요청은 Sans KR과 Mono로 나누고 Mono는 `text=0123456789`로 숫자 글리프만 요청한다. 숫자만 담은 `.num`, 날짜 입력, 단계 번호에만 Mono를 적용한다. 한글 문장·태그·출처·메타 컨테이너는 본문 폰트를 사용한다. 외부 로딩 실패 시 Apple SD Gothic Neo·Noto Sans KR·Malgun Gothic·sans-serif 및 수치의 monospace로 대체한다.

## 신뢰 상태와 다크 모드

| 의미 | 라이트 | 다크 | 색 이외의 표시 |
| --- | --- | --- | --- |
| 공식 규정 | Navy 900 / Sky 050 면 | Navy 050 / Navy 900 면 | 방패 + 공식 규정 |
| 검증 완료 | Green 700 / Green 050 면 | Green 500 / Navy 900 면 | 방패 + 검증 완료 |
| 검토·재검토·차단 | Coral 700 / Coral 050 면 | Coral 500 / Navy 900 면 | 경고 아이콘·상태 문구·사유 |
| 미검증 | Ink 700 / White 면 | #B9C4D3 / Navy 900 면 | 시계 + 미검증 + 점선 경계 |
| 정보·안내 | Sky 700 / Sky 050 면 | Sky 500 / Navy 900 면 | 구체적인 안내 문장 |

홈의 검증 배지는 검색 강조를 위해 네이비로 중립화한다. 검증 상태와 최신성은 각각 표시하며, AI 결과와 사람 승인을 구별한다. 공식 원본 불일치는 위조 확정이 아닌 출처 확인 필요로 안내한다.

다크 모드는 `prefers-color-scheme: dark`에서 Navy 900 바탕, 흰 본문, #B9C4D3 보조 문구를 사용한다. 색을 가진 글자는 500 단계, 해당 배경은 Navy 900으로 바꾼다. 500 채움 버튼에는 네이비 글자를 쓴다.

## 레이아웃 체계 · 4차

- 셸: 1024px 이상은 흰 바탕 240px 왼쪽 사이드바, 활성 메뉴는 Green 050 면과 Green 700 글자. 계정과 로그아웃은 하단. 그 미만은 하단 탭과 상단 계정 줄. `nav.tabs a` 유지.
- 콘텐츠: 최대 1200px, 좌우 32px(모바일 16px). 12열 그리드와 24px 거터.
- 헤더: Plex Sans KR 28–32px 제목, 한 줄 설명, 오른쪽 주요 행동 하나. 그 아래 필터·탭, 본문까지 32px. 동작은 기존 권한과 비활성 조건을 유지한다.
- A: 주 영역 8열과 보조 패널 4열. 상세·업로드·검토·가이드에 사용. 보조 패널은 데스크톱 sticky, 긴 패널은 자체 스크롤. 모바일은 본문 뒤에 이어진다.
- B: 같은 구성과 행 높이의 카드 그리드. 데스크톱 3열, 태블릿 2열, 모바일 1열. 홈 최근 문서·검색·보관함·결재함에 사용한다.
- 간격: 4/8/12/16/24/32/48px. 섹션 사이 32px, 큰 구획 48px, 카드 안 24px(모바일 16px).
- 카드는 얇은 1px 경계만 사용하고 그림자를 겹치지 않는다. 패널 안 구획은 제목과 여백으로 구별한다. 메타 정보는 라벨·값 2열 정의 목록, 상태는 배지 줄, 긴 보조 설명은 접는다.

## 접근성과 선택자

본문 건너뛰기, label, role, aria-current, aria-live, 키보드 밑줄 조작, 비활성 상태를 유지한다. 조작 영역 최소 44px, 모바일 줄바꿈과 reduced-motion 규칙을 유지한다.

QA 선택자는 변경하지 않았다: `#u #p #f #t .issues .progress .doc-title a #why-h #decide-h button.linklike .fix.on nav.tabs a .card-link`. 주요 메뉴는 계속 `nav.tabs` 내부 `a`이며 메뉴 목록은 `.nav-links` 래퍼 안에 유지했다. '분석 시작', '검토 마치고 게시 요청', '승인', '반려' 버튼 문구를 유지한다. QA 스크립트는 수정하지 않았다.

## 검증 및 한계

4차 적용 후 `cd apps/web && npx tsc --noEmit -p . && npx next build`, 루트 `npx eslint apps/web`, `git diff --check`를 통과했다. 모든 변경은 `apps/web`에 한정하며 커밋하지 않았다.

로컬 프로덕션 서버 실행은 샌드박스의 `listen EPERM`으로 차단되었다. 따라서 1280×720·모바일의 실제 브라우저 렌더링, 외부 폰트 로딩, 로그인·API 통합 QA는 확인하지 못했다. 홈은 최근 3개와 축약 요약·간격으로 해당 크기에 맞추도록 설계했으며 실제 콘텐츠 길이에 따른 높이는 브라우저 확인이 필요하다.
