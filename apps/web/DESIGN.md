# Hanaeum Wiki 디자인

## 1. 기존 화면 진단

app 전체 화면, globals.css, issues.tsx, seal.tsx, API·역할 분기와 두 QA 스크립트를 읽고 진단했습니다. **코드·마크업 기반 진단**이며 브라우저로 관찰한 결과는 아닙니다.

- **위계**: 모든 화면이 44rem 폭에 제한되고 검색 결과·근거·검토 사유·결재가 같은 세로 흐름으로 이어집니다. 작성자가 고칠 곳과 승인자가 판단할 부분의 구분이 약합니다. 승인자의 홈에서도 처리할 일보다 검색이 먼저 나옵니다.
- **상태 가독성**: 60px 원형 인장 안에 ‘공식/규정’, ‘검증/완료’가 두 줄로 나뉘고 회전합니다. 제목과 상태를 함께 훑기 어렵고, 카드 오른쪽 84px가 항상 비워집니다. 360px에서 긴 한국어 제목과 본문 폭이 특히 좁아집니다.
- **색 의미**: 공식 규정의 붉은 인장과 수정 경고의 붉은 강조가 충돌합니다. 미검증과 최신성 재검토도 다른 축의 정보임을 먼저 설명하지 않습니다.
- **타이포·대비**: 명조 제목·인용과 고딕 메타가 반복 교차해 정보량이 많은 업무 화면의 빠른 훑어보기에 불리합니다. Google 폰트 다운로드는 제한된 네트워크에 외부 의존성을 만듭니다. 보조 문구와 입력 경계를 명확히 분리할 필요가 있습니다.
- **간격·밀도**: 장부의 이중 세로선과 연속 가로선이 내용을 촘촘하게 묶습니다. 문제·근거·수정 방법의 시각적 구분과 구역 간 여백이 부족합니다.
- **버튼·입력**: 밑줄 입력은 기입 영역을 명확히 보여주지 않습니다. 홈·검색·가이드는 Enter로만 제출하므로 동작을 발견하기 어렵습니다. 주 행동·보조 행동·이동 링크에 일관된 구분이 필요합니다.
- **반응형**: 모바일 종류 필터는 가로 스크롤이고, 데스크톱에서도 목록과 세 칸 비교가 좁은 폭을 유지합니다. 문서 밑줄에는 클릭만 연결되어 키보드 진입 경로가 부족합니다.
- **문구**: 실패 단계 코드, 모델 식별자, 제목 없는 문서 ID, 알려지지 않은 lifecycle이 노출될 수 있습니다. 한국어 상태와 다음 행동으로 안내해야 합니다.

### 사용자별 정보 우선순위

- **은행 실무자**: 신뢰 상태 → 현행 여부 → 제목·요약 → 근거 조문·시행일 → 적용할 업무.
- **작성자**: 진행 상태 → 게시 가능 여부 → 어느 쪽을 무엇 때문에 고칠지 → 수정·게시 요청.
- **승인자**: 출처 확인·승인 대기 건수 → 확인 사유 → 원본·근거·수정 → 승인·반려.

공식 원본 불일치는 **위조 확정 아님, 출처 확인 필요** 원칙을 유지합니다. AI 분석과 사람의 승인을 혼동시키지 않습니다.

## 2. 새 방향: 근거로 연결하는 업무 지식

밝은 업무 공간, 청록색 주 행동, 읽을 수 있는 한 줄 신뢰 배지, 독립된 경고 영역으로 구성합니다. 검증 여부와 최신성은 서로 독립된 정보로 표시합니다.

공식 규정·검증 완료는 방패와 글자, 미검증은 시계·글자·점선, 재검토·구판은 경고 아이콘과 설명으로 구별합니다. 붉은색은 차단·수정에 사용합니다. 본문·보조·링크·상태와 주 버튼의 실제 조합은 WCAG AA 4.5:1 이상을 기준으로 정합니다. 비활성 컨트롤은 별도 처리합니다.

### 타이포·간격

- 외부 폰트 요청 없음. Pretendard → 시스템 UI → Apple SD Gothic Neo → Noto Sans KR → Malgun Gothic → sans-serif.
- 기본 16px / 1.65, 보조 14px, 페이지 제목 28.8~40px / 1.3, 구역·문서 제목 약 18px. 원문은 16px / 2, 최대 80ch.
- 간격 4·8·12·16·20·24·32·40·48px. 카드 18~24px, 페이지 모바일 16px / 데스크톱 40px. 반경은 버튼 9px, 카드 12px, 주요 면 16~24px.

### 컴포넌트·아이콘 규칙

- 주 행동은 청록 채움, 보조 행동은 카드 면·경계, 본문 이동은 밑줄 링크. 입력은 경계가 있는 독립 영역입니다. 터치 가능한 컨트롤은 44px 이상입니다.
- 상태를 카드 위에, 날짜·분류를 제목 아래 보조 정보에 배치합니다. 카드 전체 이동과 카드 안 개별 동작의 우선순위를 유지합니다.
- `app/icons.tsx`: 24×24 viewBox, 1.8px 선, 둥근 끝의 인라인 SVG. 설치 의존성 없음. 장식 아이콘은 aria-hidden이고 읽을 수 있는 문구와 병기합니다.
- 사유는 번호 → 문제 → 근거 인용 → 수정 안내. 원본·근거·수정은 모바일 세로 배치, 데스크톱 세 칸입니다. 버전 비교의 추가 밑줄·삭제 취소선을 유지합니다.
- 폼 label·aria·상태 알림을 유지합니다. 본문 건너뛰기와 밑줄 Enter/Space 조작을 추가합니다. reduced-motion에서는 전환·애니메이션과 강제 부드러운 스크롤을 제거합니다.

### 레이아웃

기본은 단일 열이며 제목·메타·파일 입력·필터가 줄바꿈하도록 min-width:0, minmax(0,1fr), overflow-wrap을 적용합니다. 가로 스크롤 필터는 줄바꿈으로 바꿉니다. 600px부터 필터·빠른 이동 두 열, 760px부터 등록 절차 세 열, 1000px부터 248px 사이드 메뉴·최대 1240px 콘텐츠·문서 카드 두 열·비교 세 칸입니다. 좁은 화면은 하단 메뉴입니다. 업무 가이드 진입점을 메뉴에도 추가합니다.

## 4. 선택자와 검증

### 변경한 QA 선택자 목록

**없음.** 두 QA 스크립트는 수정하지 않았습니다.

`#u`, `#p`, `#f`, `#t`, `.issues`, `.progress`, `.doc-title a`, `#why-h`, `#decide-h`, `button.linklike`, `.fix.on`, `nav.tabs a`, `.card-link`, `li.entry`, `dl.meta-grid`, `p[aria-live]`, `.seal`과 기존 aria-label을 유지합니다. ‘분석 시작’, ‘검토 마치고 게시 요청’, ‘승인’, ‘반려’, ‘결재함’, 메뉴의 ‘등록’·‘관리’ 문구도 유지하며 ‘가이드’ 메뉴만 추가했습니다.

### 실행 기록

- 로컬 Next.js 16의 CSS, Layouts and Pages 문서를 확인했습니다.
- `cd apps/web && npx next dev`: 0.0.0.0:3000 listen EPERM. 127.0.0.1 지정도 동일하게 차단됩니다. mock 브라우저 관찰, 실제 360px overflow·다크 모드 시각 확인과 E2E 실행은 **미완료**입니다.
- `cd apps/web && npx tsc --noEmit -p . && npx next build`: 통과. 전체 9개 화면 경로 정적 생성 성공.
- 저장소 루트 `npx eslint apps/web`: 통과. `git diff --check`: 통과.
- 주요 본문·보조·링크·상태·버튼의 라이트·다크 색 조합을 상대 휘도 공식으로 계산했습니다. 최초 청록 글자와 연한 브랜드 면의 대비가 4.37:1이어서 청록 토큰을 #007570으로 조정했습니다. 최종 주요 조합은 모두 4.5:1 이상입니다. 브라우저 접근성 감사 전체를 대신하지는 않습니다.
- 커밋하지 않고 작업 트리에 남깁니다.
