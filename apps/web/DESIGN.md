# Codex 제안 · 상세 항목 카드와 팝업 (2026-11-17)

## 배치와 판단

문서 상세와 결재 대상 상세의 오른쪽은 현재 쪽·고칠 곳 수·참고 건수만 표시한다. 길이를 예측하기 어려운 쪽 요약·핵심어·인용 조문도 본문 아래로 옮겼다. 본문 아래에는 제목만 있는 흰색 카드들을 배치한다. 쪽 요약, 고칠 곳, 확인된 근거·실무 보완, 확인이 필요한 이유, 버전·바뀐 곳, 검증 정보, 비교한 대상, 관련 문서, 외부 법령 참고를 각각 선택해서 읽는다. 이미 비어 있음을 아는 고칠 곳·참고·비교 대상·관련 문서·복수 버전 카드는 숨긴다. 외부 법령은 열 때 조회하며 결과가 없으면 팝업에 안내한다.

밑줄을 선택하면 번호·활성 상태를 유지하면서 고칠 곳 팝업을 열고 해당 항목으로 스크롤한다. 결재 사유의 위치 버튼도 해당 쪽과 고칠 곳 팝업으로 연결한다. 승인·반려·출처 반려와 삭제·원본 다운로드는 팝업 밖의 기존 동작을 유지한다.

네이티브 dialog의 포커스 제한과 함께 닫기 버튼 초기 포커스, Esc 닫기, 제목 aria-labelledby 연결, 닫은 뒤 실행 요소로 포커스 복귀, 열려 있는 동안 배경 스크롤 잠금을 적용했다. 흰 바탕·Hana 색과 폰트를 유지하고 한쪽 색 띠나 의존성을 추가하지 않았다. API 호출·타입과 권한·판정 로직, 원문 위치 기반 본문 렌더러는 유지했다.

## QA와 검증

qa-flow.mjs의 D1~D9를 유지하며 검증 정보·비교 대상·쪽 요약·외부 법령·확인된 근거 카드를 열어서 내용을 읽도록 변경했다. 쪽 본문과 요약은 모든 쪽을 넘기며 렌더링도 확인한다. qa-admin.mjs는 확인이 필요한 이유 카드를 열어 #why-h를 읽고 위치 버튼에서 .fix.on으로 연결한 뒤 팝업을 닫아 #decide-h를 확인한다.

타입 검사, Next 프로덕션 빌드, apps/web 및 tests/e2e ESLint, doc-text 테스트 4개, 두 QA 스크립트 문법 검사를 통과했다. 실제 API E2E와 브라우저 시각·키보드 검수는 실행하지 않았다. 변경은 apps/web·tests/e2e 안에 한정했고 커밋하지 않았다.

# Codex 제안 · 문서 상세 읽기 개선 (2026-11-17)

## 진단

긴 조문 한 줄 전체를 제목으로 렌더링해 조·항·호의 구분이 사라지고 본문까지 굵어졌다. 본문 옆 확인 패널은 중간 화면에서도 폭을 차지해 긴 문장의 줄바꿈을 늘렸다. 긴 규정에서 원하는 조문으로 이동할 방법도 없었다. 상단·왼쪽 색 띠는 내용보다 상자를 강조했다.

## 고른 방법과 이유

원문 순서를 유지하는 읽기 면을 사용한다. 조 번호·괄호 제목만 소제목으로 두고 뒤의 항 본문은 보통 굵기로 분리한다. 장·절은 제목 전체를 유지한다. 규정은 이 쪽 목차를 펼쳐 조문으로 이동하며, 조문이 없는 짧은 노하우에는 목차를 표시하지 않는다. 원문 offset을 다시 계산하거나 텍스트를 재작성하지 않고 동일한 인라인 렌더러를 구간별로 호출해 밑줄의 번호·클릭·키보드 조작을 보존한다.

## 바꾼 것

- 보관함·결재 대상 상세에 쪽별 접이식 조문 목차와 원문 위치 기반 앵커 추가.
- 공통 본문 렌더러에서 조 제목과 항 본문 분리. 읽기 본문 17px·줄간격 1.9·최대 66ch, 조 사이 여백 확보. 검토 미리보기도 조문 구조 개선을 공유.
- 1200px 미만에서는 요약·고칠 곳·근거를 본문 아래로 배치. 넓은 화면은 보조 열 300px를 확보. 버전·관련 문서·외부 법령·검증·결재 위치와 기능 유지.
- 모든 화면의 상자·인용·수정 항목·단계 표시에서 한쪽 색 띠 제거. 상태는 기존 문구·색 글자·옅은 면으로, 활성 고칠 곳은 전체 테두리로 구분. 중립 구분선은 유지.
- 흰 바탕, Hana 색 토큰·폰트, API·상태·권한·접근성 속성·QA 선택자·버튼 문구 유지. 새 의존성과 커밋 없음.

## 확인

다음 검사를 모두 통과했다.

- `cd apps/web && npx tsc --noEmit -p . && npx next build`
- 루트 `npx eslint apps/web`
- `node --test apps/web/doc-text.test.mjs` — 4개 통과. 긴 조문 분리와 여러 구간에 걸친 원문 밑줄 보존 검사를 추가했다.
- `git diff --check`

브라우저 시각 검수와 실제 API E2E는 수행하지 않았다. 반응형은 코드로 점검했으며 실제 화면 검증 완료로 간주하지 않는다. 변경은 `apps/web` 안에 한정했고 커밋하지 않았다.

# Codex 제안

2026-11-17 · 기존 미커밋 결과를 이어받아 홈·검색·보관함 목록/상세·등록·검토·결재함·가이드·로그인의 JSX, 공통 CSS, 권한 셸, 본문 렌더러와 QA 선택자를 코드로 점검했다. 아래 제안과 적용 기록이 이전 기록보다 우선한다.

## 진단한 문제

- 홈을 한 화면에 넣기 위한 12–13px 글자 축소가 읽기 편한 화면이라는 목적을 해쳤다. 검색 영역과 최근 문서의 위계도 약했다.
- 검색 결과와 보관함을 똑같은 3열 카드로 표시해 긴 근거 조문·메타를 읽기 어려웠다. 서로 다른 작업에 같은 레이아웃을 적용했다.
- 상세는 페이지 제목과 문서 제목이 반복되고, 긴 메타가 본문을 아래로 밀었다. 쪽 본문과 확인 항목의 폭 배분도 읽기에 불리했다.
- 결재함의 두 줄 생략이 승인 판단에 필요한 사유를 가렸다. 로그인은 큰 회색 안내 면이 입력 폼과 경쟁했다.

## 정한 방향과 이유

흰 캔버스 위에 **검색 → 근거 확인 → 사람의 검토**라는 위키의 실제 작업을 드러낸다. 모든 정보를 가로 카드로 만드는 대신, 검색은 문장을 읽는 결과 목록, 보관함은 문서를 훑는 2열 카드, 상세·검토·가이드는 주 작업과 보조 도구의 비대칭 2열로 구분한다. 홈만 최근 문서 3개를 나란히 보여 준다. 좁은 화면에서는 읽기와 조작에 필요한 폭을 확보하도록 열을 접는다. 세로 메뉴는 유지한다.

저장소 밖 `Hana Design Guide.pdf`를 `pdftotext -layout`으로 직접 확인했다. PDF는 복사하지 않았다. 가이드의 흰 바탕, Navy 900 제목, Ink 700 본문, Green 700 주요 행동, Sky 정보·출처, Coral 주의, Violet 조문·키워드 원칙과 기존 폰트 스택을 유지한다. 밝은 500 색은 본문 글자로 사용하지 않는다. 슬라이드용 24px 최소 본문은 웹에 그대로 옮기지 않고 본문 16px·보조 14px로 적용한다. 외부 폰트가 차단되어도 시스템 한글 폰트로 표시된다.

검색은 문서 1건 아래 일치 조문·인용을 순서대로 묶고, 보관함 카드는 전체 판 수, 상세 버전 목록은 시행일·오늘 시행 중인 판·보고 있는 판을 구분해 표시한다.

# Hanaeum Wiki · Hana Design Guide 웹 적용

## 기준과 범위

저장소 밖의 `Hana Design Guide.pdf`(디지털 발표 디자인 가이드 v1.0)를 직접 읽었다. PDF는 복사·추가하지 않았다. 슬라이드의 1280×720와 본문 24px를 웹에 그대로 적용하지 않고 색·위계·강조 원칙을 적용했다. 변경은 `apps/web`에 한정한다. API 호출 경로·타입, 권한 분기, 분석·검토·승인 로직, Hanaeum Wiki 이름과 SYNTHETIC 고지를 유지한다. 실제 은행 로고는 사용하지 않는다.

## 색 토큰과 면적

`app/globals.css`에 가이드 토큰을 정의하고 기존 컴포넌트 변수는 해당 토큰의 별칭으로 연결했다.

| 계열 | 700 · 글자·아이콘·선 | 500 · 면·막대 | 050 · 옅은 배경 |
| --- | --- | --- | --- |
| Green | #00706B | #00A19B | #E6F5F3 |
| Sky | #1E63D6 | #6BA4F6 | #E9F1FE |
| Violet | #5B4BC4 | #9A8DE8 | #EFEDFB |
| Coral | #C2410C | #F26D1B | #FDEEE2 |

Navy: `--navy-900:#0A1C36`, `--navy-600:#274F80`, `--navy-050:#E8EDF4`. Ink: `--ink-700:#33465B`, `--ink-500:#64748B`. 경계: `--line:#DCE3ED`.

흰 화면·카드와 네이비 본문을 기본으로 한다. White 60 / Navy 20 / Green 12 / 보조 합계 8 이내를 강조 면적 기준으로 삼되 빈 화면을 비율에 맞춰 칠하지 않는다. 홈에서 그린 강조는 검색 영역 한 곳이다. 홈의 검증 배지도 아이콘·문구와 Green 신뢰 색을 유지한다. 메뉴·계정·일반 버튼은 네이비다. 보조색은 정보 Sky·주의 Coral·키워드와 조문 Violet을 역할에 맞게 사용한다. 범주 시각화의 순서는 Green → Sky → Violet → Coral → Navy, 초과 범주는 기타 #B9C4D3이다.

라이트에서 500 단계는 글자로 쓰지 않는다. 050 면에는 같은 계열 700 글자를 쓴다. 본문·상태의 색 조합은 대비 4.5:1 이상을 기준으로 선택한다. 면적 비율과 대비는 브라우저 픽셀 측정 결과가 아닌 설계 기준이다.

## 폰트와 숫자

- 제목 `--font-display`: IBM Plex Sans KR 600/700. 페이지 28–32px, 섹션 19.2px, 카드 18px.
- 본문 `--font-body`: Pretendard / Pretendard Variable 400/500/700. 본문 16px, 보조 14px, 고지 13px.
- 숫자 `--font-num`: IBM Plex Mono 500/600. 건수·날짜·쪽수·진행률·단계 번호에 사용한다.

`app/layout.tsx` head에 Google Fonts preconnect·stylesheet와 지정된 Pretendard CDN stylesheet를 추가했다. 패키지 설치나 빌드 시 다운로드는 없다. Google Fonts 요청은 Sans KR과 Mono로 나누고 Mono는 `text=0123456789`로 숫자 글리프만 요청한다. 숫자만 담은 `.num`, 날짜 입력, 단계 번호에만 Mono를 적용한다. 한글 문장·태그·출처·메타 컨테이너는 본문 폰트를 사용한다. 외부 로딩 실패 시 Apple SD Gothic Neo·Noto Sans KR·Malgun Gothic·sans-serif 및 수치의 monospace로 대체한다.

## 5차 · 흰 바탕 고정과 글자 색 역할

OS 설정에 관계없이 흰 바탕 #FFFFFF를 사용한다. 모든 dark 미디어 규칙을 제거하고 html의 `color-scheme: light`, viewport themeColor #FFFFFF를 지정했다. 구획은 Navy 050·Green 050 같은 옅은 면만 사용한다.

| 역할 | 글자 색 | 보조 표현 |
| --- | --- | --- |
| 페이지·섹션 제목 | Navy 900 #0A1C36 | 크기·굵기·여백 |
| 본문 | Ink 700 #33465B | 16px, 문서 줄간격 1.7 |
| 설명·메타 | Ink 500 #64748B | 작은 메타·라벨은 Ink 700 |
| 주요 행동·링크 | Green 700 #00706B / Navy 600 #274F80 | 주 버튼 Green, 일반 링크 Navy·밑줄 |
| 정보·안내 | Sky 700 #1E63D6 | Sky 050 면과 안내 문구 |
| 키워드·조문·태그 | Violet 700 #5B4BC4 | Violet 050 면 또는 조문 번호 |
| 주의·수정·차단 | Coral 700 #C2410C | Coral 050 면과 경고·사유 |
| 숫자 | Navy 900 | IBM Plex Mono |

흰 바탕 대비 4.5:1 이상인 700 계열을 글자에 사용한다. Ink 500은 보조 정보 예외이며 작은 글자는 Ink 700로 높인다. 한 문장 안 색 혼용을 피하고, 조문 번호처럼 구조를 구분할 때만 별도 색을 쓴다. Green 강조는 화면의 주요 행동에 집중하며 메뉴 활성·검증 배지는 의미 표시로 유지한다.

신뢰 배지는 공식 규정 Navy 600/Navy 050 + 방패, 검증 완료 Green 700/Green 050 + 방패, 검토 필요 Coral 700/Coral 050 + 경고, 미검증 Ink 500/Navy 050 + 시계·점선으로 표시한다. 홈도 같은 의미를 유지한다. 미검증의 중립 050 면은 Navy 050을 사용한다.

## 5차 · 문서 본문 렌더 규칙

`app/doc-text.tsx`의 순수 함수 `parseDocText(text)`가 줄의 원문 UTF-16 시작·끝 offset을 보관한다. 보관함·결재 상세와 검토 미리보기에서 같은 렌더러를 쓴다. 새 의존성은 없다.

- #/##/### 제목, 제N조(제목)·제N장·제N절, 원문 번호가 있는 목록과 불릿, 인용, 빈 줄, 일반 문단을 구분한다.
- 연속된 파이프 줄은 표로 표시한다. 고립된 파이프 줄은 원문 그대로 둔다. 셀은 줄바꿈하여 모바일에서도 읽는다.
- **굵게** 기호는 숨기고 굵은 글자를 표시한다. 대괄호 마스킹 표시는 회색 배지다. HTML은 React의 일반 문자열로 출력한다.
- 기호를 숨겨도 offset은 원문 기준이다. 밑줄을 각 줄·인라인 구간·셀 경계로 잘라 같은 번호를 붙인다. 겹침은 앞 밑줄 우선이며 `.hl`, `.on`, 클릭·Enter·Space·onPick 동작과 `mark-n` 수정 항목 id를 유지한다.
- 본문은 흰 면, 최대 72ch, 줄간격 1.7이다. 제목과 조문 번호·여백으로 위계를 보여 준다.
- `node --test apps/web/doc-text.test.mjs`: CRLF·굵게·마스킹·여러 줄 밑줄, 표·목록·조문, 겹침·HTML escaping과 원문 글자의 중복·누락을 검사한다(숨긴 기호와 블록 경계 제외).

## 5차 · 레이아웃 재정의

셸은 흰 왼쪽 메뉴와 1px Line #DCE3ED 경계, Green 050/700 활성 메뉴, 본문 최대 1200px를 유지한다. 작은 화면에서는 기존 하단 메뉴와 계정 줄을 유지한다. 페이지 머리는 Navy 제목·설명·오른쪽 행동, 필요한 상태 칩은 그 아래 한 줄이다.

정보 위계는 색·크기·여백으로 만든다. 카드 경계는 1px Line, 그림자는 없으며 카드 안의 정보·수정 항목은 구분선과 여백으로 구별한다. 360px에서는 열을 하나로 쌓고 긴 문자열·표 셀을 줄바꿈한다.

| 화면 | 구성 |
| --- | --- |
| 홈 | 검색 → 할 일 칩 → 최근 문서 3블록 유지 |
| 검색·보관함·결재함 목록 | 배지 → 제목 → 근거·메타 → 두 줄 요약 → 행동 순서. 기존 결재 단계와 버튼은 유지 |
| 상세 | 전체 폭 문서 머리(신뢰·제목·요약·일자·다운로드) → 결재 확인 이유 → 쪽 본문과 쪽 요약·고칠 곳 2열 → 접이식 버전·관련 문서·외부 법령. 결재·검증·삭제는 하단 |
| 검토 | 확인할 내용과 마크다운 미리보기, 상태·게시 요청 패널 |
| 업로드·가이드 | 주 작업과 보조 패널 유지, 내부는 중첩 카드 없이 제목·여백으로 구별 |

## 접근성과 선택자

본문 건너뛰기, label, role, aria-current, aria-live, 키보드 밑줄 조작, 비활성 상태를 유지한다. 조작 영역 최소 44px, 모바일 줄바꿈과 reduced-motion 규칙을 유지한다.

QA 선택자는 변경하지 않았다: `#u #p #f #t .issues .progress .doc-title a #why-h #decide-h button.linklike .fix.on nav.tabs a .card-link`. 주요 메뉴는 계속 `nav.tabs` 내부 `a`이며 메뉴 목록은 `.nav-links` 래퍼 안에 유지했다. '분석 시작', '검토 마치고 게시 요청', '승인', '반려' 버튼 문구를 유지한다. QA 스크립트는 수정하지 않았다.

## Codex 제안 · 목록 페이지네이션과 결재 카테고리 (2026-11-17)

- 보관함·검색 결과·검색어 없는 전체 문서·관련 검색 결과는 한 쪽 6건이다. 상세 팝업의 관련 문서도 종류별 6건으로 나눈다. 필터와 검색어 변경 시 기존 주소 생성 방식으로 쪽 쿼리를 제거하여 1쪽으로 돌아간다.
- 홈 최근 게시 문서는 전체 데이터를 3건씩, 내가 올린 진행 문서는 6건씩 보여 준다. 기존 최근 3건 제한 대신 모든 게시 문서를 쪽으로 탐색할 수 있다.
- 결재함은 출처 확인 필요 → 게시 승인 대기 → 승인 뒤 게시 진행 → 자동 차단 순서의 기존 구분을 유지한다. 좌우 작업판을 전체 폭 카테고리로 바꾸고 카테고리마다 3건씩 보여 준다. 넓은 화면 3열, 중간 화면 2열, 작은 화면 1열이며 가로 스크롤은 없다. 결재 단계·사유·승인·반려 버튼을 카드 안에 유지하고 사유는 자르지 않는다.
- 목록 아래에 전체 건수·현재/전체 쪽, 이전·쪽 번호·다음을 배치한다. 쪽 번호는 처음·마지막과 현재 앞뒤 2쪽만 표시하고 생략 기호를 둔다. 흰 바탕·기존 Hana 폰트·테두리를 유지하고 현재 쪽만 Green으로 표시한다. 한쪽 색 띠와 새 의존성은 없다.
