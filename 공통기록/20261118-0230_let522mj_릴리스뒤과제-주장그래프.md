# let522mj: 릴리스 뒤 과제 — 주장(Claim) 그래프로 "어떤 문서를 읽어야 하는지" 판단

상태: 보류 (사용자 결정 11/17: MVP는 검증된 지식을 모으고 연결하는 데 집중, 주장 단위는 얇은 버전만)

## 이미 있는 발판 (MVP에 들어감)
| 항목 | 위치 |
|---|---|
| 조문 단위 그래프 (법령→개정본→조·항·호, 노하우 CITES) | mcp/graph-server |
| 노하우 주장 ↔ 조문 관계 저장 (SUPPORTS·SUPPLEMENTS·CONFLICTS·INSUFFICIENT) | claims 테이블, interfaces 10.2 (dhxorb96) |
| 개정 시 바뀐 조문의 주장 재검토 표시 | GraphUpsert markRevisedClaims (PR #36) |

## 릴리스 뒤 단계 (권고)
| 단계 | 내용 |
|---|---|
| 1 | 검색 결과·가이드 근거에 "근거 n / 반대 근거 n" 표시 (claims 집계, 인용 대조 통과분만 근거) |
| 2 | 같은 조문 기준 중복 주장 묶기, 조문 속 수치 조건("5억원 이상인 경우") 필터 |
| 3 | 서술형 적용 조건(APPLIES_WHEN), 충돌 해결 안내, 업무 체크리스트, Neptune CLAIM 노드 |

## 원칙
- 주장은 원본 문서 승인에 묶고, 원문 인용과 글자 대조를 통과한 것만 "근거"로 쓴다
- 자유 문장 통합은 오판 위험이 커서 같은 조문에 걸린 주장끼리만 시작
