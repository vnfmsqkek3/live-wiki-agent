## 요청 (apps/api·apps/web·Classify)
1. **제목 자동**: 업로드 화면 제목 입력을 선택으로. 비우면 분석 후 제목 채움 — Classify 구조화 출력에 `title`(문서 내용을 대표하는 30자 이내) 추가, 실패 시 `titleCandidate(pages, filename)`. 작성자 검토 화면에서 수정 가능, 수정 이력 저장
2. **문서 일자**: `library.ts docDate`를 `docDates`/`primaryDate`로 바꾸고(라벨 6종·형식 4종·없는 날짜 제외), Documents에 `doc_date`·`doc_dates` 저장 → 카드·상세에 "시행 2026-12-01 · 개정 2026-11-01"
3. **버전 관리**
   - 데이터: Documents `series_id`(첫 버전 doc_id), `version_no`, `previous_doc_id`. 새 버전 게시(승인) 시 이전 버전 `freshness=SUPERSEDED`·`superseded_by` (검색은 이미 SUPERSEDED·현재 해시만 노출)
   - 업로드: 분석 후 `previousVersionCandidates`(본인이 볼 수 있는 같은 종류 PUBLISHED 문서)로 "이 문서의 새 버전인가요? (기존: 제목, 본문 87% 일치)" → 작성자가 확인하면 연결. 자동 연결 안 함
   - 업로드 검토 화면: 연결된 경우 `diffDocuments(이전 쪽, 새 쪽)` 결과 "바뀐 곳 N건" — 위치(제12조제1항 / 3쪽)·종류(추가·삭제·변경)·이전 → 새 문구, 수치 변화 강조
   - 보관함 상세: "버전 v1 · v2 · v3" 선택 + 직전 버전과 변경점 같은 형식, 바뀐 문장 밑줄(Mark kind 추가 `VERSION_CHANGE` 필요하면 알려 주세요)
   - 승인자 결재함에도 "이전 버전 대비 바뀐 곳" 요약
4. **검색 세부 필터 화면**: 종류(기존) + 업무 분류, 부서, 문서 일자 기간, 검증 상태(검증됨/미검증), 최신성(현행/재검토 필요). `/v1/search`가 그대로 `search_wiki` 인자로 전달. 키워드 보완 결과(`kw`)에도 같은 조건 적용

## 기본값으로 정한 것 (사용자 확인 전)
- 버전 연결은 작성자 확인 후에만 (오연결 방지). 새 버전도 승인 전에는 검색에 안 나옴, 승인 시 이전 버전 SUPERSEDED
