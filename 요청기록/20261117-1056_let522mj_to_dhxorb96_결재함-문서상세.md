## 요청 (apps/web·apps/api)
1. **결재함 항목 클릭 → 상세**: 두 목록의 제목(카드 전체)을 `/library?id={doc_id}`로 연결. 상세에서 돌아오면 결재함으로
2. **상세 권한**: `/v1/library/:id`에서 APPROVERS(REG_APPROVER·SECURITY_REVIEWER)는 결재 대상 문서(IN_REVIEW 중 PENDING 승인 또는 출처 확인 대기, BLOCKED)도 열람. 목록(`/v1/library`)은 지금처럼 유지 (결재 대상이 보관함 카드에 섞이지 않게). 열람은 감사 기록
3. **상세 상단 "확인이 필요한 이유" 요약**: 결재 대상일 때 쪽 본문 위에 항목 수와 목록(예: "3쪽 제12조제1항: 공식 원본은 5억원, 업로드 본은 3억원")을 두고, 누르면 해당 쪽·밑줄로 이동. 위치를 못 찾은 항목은 기존 `doc_marks` 구역
4. **상세에서 바로 결재**: 승인·반려(출처 불일치는 반려만) 버튼을 상세 하단에도 둔다. 사유 입력 그대로
5. 쪽 본문이 없는 문서(파일 구조 검사에서 차단돼 분할 전 멈춤): 쪽 대신 finding의 `user_message`·`fix_hint`·쪽 번호 목록을 보여 준다
