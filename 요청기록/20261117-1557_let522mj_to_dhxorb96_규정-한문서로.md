## 확인한 사실 (공유 dev, 재업로드 후)
| 화면 | 현상 | 원인 |
|---|---|---|
| 검색 `/v1/search` "기업여신 승인 기준" | 상위 10건 중 9건이 같은 문서(기업여신 심사규정 2026-11-01, DSF9GZ) — 조문 조각마다 카드 1장 | `search_wiki`는 근거 인용용으로 **조문 단위** 결과를 돌려줌. API가 이를 그대로 카드로 나열 |
| 보관함 `/v1/library?type=REGULATION` | 기업여신 심사규정 3장(2025-01-01·2026-11-01·2026-12-01), 수신·외환·카드·신용리스크 각 2장 | 개정본마다 문서 1건. 같은 `law_id`인데 `series_id`가 비어 있어 버전으로 묶이지 않음 (규정은 작성자 연결 단계를 거치지 않음) |

## 요청
1. **검색 결과를 문서 단위로 묶기**: `/v1/search`가 `items`를 `doc_id`로 묶어 카드 1장. 카드 안에 맞은 조문 목록(조문 표기·한 줄 인용, 상위 3개 + "외 N곳"). 순서는 문서의 최고 점수. `related`도 같은 방식. 가이드 근거는 지금처럼 조문 단위 유지
2. **규정은 같은 law_id = 한 문서(버전 묶음)**: 보관함·검색 카드의 묶음 키를 `series_id ?? (document_type==='REGULATION' && law_id ? 'LAW#'+law_id : doc_id)`로. 카드에는 **오늘 시행 중인 버전**(effective_from ≤ 오늘 ≤ effective_to, 없으면 최신)을 대표로, 상세에서 버전 v1·v2·v3 선택과 직전 버전 대비 바뀐 곳(`diffDocuments`). Registry `law_id`는 공식 근거라 작성자 확인 없이 자동으로 묶어도 됨
3. 노하우·매뉴얼은 지금처럼 작성자가 확인한 `series_id`로만 묶음

## 참고
- 데이터는 이미 있음: PostgreSQL documents에 규정 19건 모두 `law_id`·`revision_id` 채워져 있음 (SYN-LOAN-001 3건, FX·DEP·CARD·RISK 각 2건, 나머지 1건)
- 검색은 기준일(as_of)로 현행 버전만 근거로 나오므로 버전 중복은 없음 — 쪼개짐은 조문 조각 단위 나열 때문
