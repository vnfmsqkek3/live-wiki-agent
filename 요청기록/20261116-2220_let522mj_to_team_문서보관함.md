## 2. 데이터 계약 v0 (이견은 이 파일에)

`GET /v1/library?type=&business=&tag=&q=` (권한 내 PUBLISHED + 본인 문서)
```
{ items: [{ doc_id, title, document_type, business_path[], tags[], summary, authority_status, freshness, effective_from,
            mark_count, related: [{ doc_id, title, relation: "CITES"|"CITED_BY"|"CONFLICTS"|"SIMILAR", reason }] }] }
```
`GET /v1/library/{doc_id}`
```
{ ...카드 필드, pages: [{ page, text /*마스킹본*/, summary,
    marks: [{ start, end /*page text 글자 위치, 범위 없으면 null=페이지 전체*/, severity: "HIGH"|"MEDIUM"|"LOW",
              kind: "CONFLICT"|"OUTDATED"|"INSUFFICIENT"|"REGISTRY_MISMATCH"|"PII_UNCERTAIN"|"INJECTION",
              reason, basis?: { provision_id, label, text, effective_from }, fix? }] }] }
```

| 필드 | 출처 | 담당 |
|---|---|---|
| pages[].text | `{doc_id}/masked/segments/{n}.json` (페이지 단위로 이미 저장됨) | dhxorb96 API 조회 |
| summary, pages[].summary | **신규 Summarize 단계** (마스킹본 → Haiku, 문서 요약 3~5문장 + 페이지별 1~2문장) → Documents 저장 | dhxorb96 (모델 호출 단계), yoyo0704 (단계 Lambda·Gateway Target 등록) |
| business_path, tags | Classify 결과 (이미 있음) | dhxorb96 |
| marks | `@hanaeum/regulation-server` **`buildMarks(pages, sources)`** — 노하우 판정 문장(CONFLICT·INSUFFICIENT), 개정 전 인용(OUTDATED, fix=현행 조문), 규정 위조 조문 차이(REGISTRY_MISMATCH, fix=공식 원문), 페이지 Finding(PII·Injection)을 페이지·글자 위치로 변환 | **let522mj** |
| related | knowhow_validation 근거 조문(CITES/CONFLICTS) + search_wiki(제목+요약, 자기 자신 제외)의 상위 문서(SIMILAR). 규정 문서는 그 규정을 인용한 노하우(CITED_BY, 영향 그래프 연동 후) | dhxorb96 조합, let522mj search Tool |

## 3. 원칙
- 원문이 아니라 **마스킹본만** 표시·모델 입력. 권한 밖 문서는 related에서도 제외 (search Tool ACL).
- 밑줄 근거는 조문 원문을 그대로 보여 주고 시행일을 함께 표시. 모델이 만든 이유만으로 밑줄을 확정하지 않는다 (인용 원문 대조 통과분만).
